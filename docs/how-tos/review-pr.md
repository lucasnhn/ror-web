# How to - review PR

When reviewing a PR, your goal is to ensure the code is correct, clean, and understandable.

## PR Review Checklist
- [ ] Does the PR description clearly explain the changes?
- [ ] Does the code solve the issue it claims to solve?
- [ ] Is the code easy to understand?
- [ ] Are there any obvious bugs or mistakes?
- [ ] Are there any leftover `console.log` or commented-out code without a TODO?
- [ ] Does the code follow the project's style guidelines?
- [ ] Are tests added or updated where necessary?
- [ ] Does the project build successfully with this code?
- [ ] Are any new dependencies justified?
- [ ] Are visual changes (if any) shown in the PR with screenshots?

## How to Comment
- Be **clear**, **polite**, and **constructive**.
- Suggest improvements if needed.
- Ask questions if something is unclear.
- Approve if everything looks good, or request changes if needed.
    - LGTM = Looks Good To Me, and is a very common comment if everything looks good

## Approving or Requesting Changes
- If everything is good, click **"Approve"**.
- If improvements are needed, click **"Request changes"** and explain why.
